# 旅行のしおりアプリ 要件定義書 v1.0

最終更新: 2026-11-05

## 1. 概要

| 項目 | 内容 |
|---|---|
| 目的 | 友人との旅行で実際に使うしおりを、みんなで作って見る |
| 利用者 | 自分＋友人2人（計3人）。一般公開はしない |
| 認証 | Googleアカウントでログイン。ログインしていない人は見られない |
| 共有 | メンバー全員がリアルタイムで同時に編集できる |
| デザイン | 機能ができてから決める（最初はシンプルな画面） |
| 画像 | 扱わない |

## 2. 技術構成

| 区分 | 採用技術 |
|---|---|
| フロントエンド | React + Vite + TypeScript |
| 認証 | Firebase Authentication（Googleログイン） |
| データベース | Cloud Firestore（`onSnapshot` でリアルタイム同期） |
| ホスティング | Firebase Hosting |
| ソースコード管理 | GitHub |
| デプロイ | GitHub Actions で main ブランチへの push 時に Firebase Hosting へ自動デプロイ |
| 料金プラン | Firebase Spark（無料）プラン |

## 3. 機能要件（MVP）

### F1. ログイン／ログアウト
- Googleアカウントでログインする（ほかのログイン方法は用意しない）
- 未ログイン時はログイン画面だけを表示する

### F2. しおり（旅行）の管理
- しおりの作成・編集・削除ができる
- 項目: タイトル、目的地、開始日、終了日、メモ
- しおり一覧には、自分がメンバーになっているしおりだけを表示する
- 削除できるのは作成者だけ

### F3. メンバー管理
- 作成者が、友人の Googleアカウントのメールアドレスを入力してメンバーに追加する
- 追加された人は、そのGoogleアカウントでログインすると一覧にしおりが表示される
- メンバーは全員、閲覧・編集ができる（権限の差はつけない）
- 作成者はメンバーを外すことができる

### F4. 旅程（日程表）
- 「1日目 11/13(金)」のような日付タブで日ごとに切り替え、予定をタイムラインで表示する
- 予定の項目: 種類（移動・食事・観光・宿泊・その他）、名前、日付、開始時刻、終了時刻、場所、URL、予約状況（予約なし・これから予約・予約済）、メモ
- 日付は旅行期間の日付をボタンで並べて選ぶ
- 時刻はモーダルで入力する。手入力欄の下に、時を1時間ずつ増減する左右の矢印ボタン（長押しで連続）と、「00〜55分（5分ごと）」のボタンがあり、押すと手入力欄の時・分が書き換わる
- 予定の追加・編集・削除ができる
- 同じ日の予定は開始時刻順に並べる（時刻なしの予定は最後に、登録順で並べる）
- 他のメンバーが変更すると、自分の画面にもすぐ反映される

### F5. 持ち物リスト
- 旅行に関係なく、Googleアカウントごとに1つのリストを持つ
- 自分のリストだけが表示され、ほかの人のリストは見えない
- 持ち物の追加・削除、チェックの付け外しができる

### 画面下のタブ
- 「旅程」と「持ち物」の2つ。「旅程」は旅の一覧、「持ち物」は自分の持ち物リストを開く

## 4. 非機能要件
- **スマホ優先**: 旅行中はスマホで見るので、スマホの画面幅で使いやすくする
- **セキュリティ**: Firestore のセキュリティルールで、メンバー以外は読めない・書けないようにする
- **同時編集**: 同じ項目を同時に編集したときは、後から保存した方が残る（3人なので問題になりにくい）
- **秘密情報**: Firebase の設定値は環境変数（`.env`）で管理する。デプロイ用のサービスアカウントキーは GitHub Secrets に置き、リポジトリにはコミットしない

## 5. 画面一覧

| 画面 | 内容 |
|---|---|
| ログイン | 「Googleでログイン」ボタン |
| 旅程（旅の一覧） | 自分が参加している旅のカード一覧、「新しい旅をつくる」ボタン |
| 旅の作成・編集 | 旅行の名前、行き先、出発日・帰着日、メモの入力フォーム |
| 旅の詳細 | 日付タブ、共有人数、予定のタイムライン、「予定を追加」ボタン |
| 予定の追加・編集 | 種類、名前、日付、時刻、場所、予約状況、メモ |
| メンバー設定 | メンバーの一覧と追加・削除（作成者のみ） |
| 持ち物 | 自分だけの持ち物チェックリスト |

## 6. データ構造（Firestore）

```
trips/{tripId}
  title: string
  destination: string
  startDate: string        // "2026-12-01"
  endDate: string
  memo: string
  ownerUid: string
  ownerEmail: string
  memberEmails: string[]   // 作成者を含む
  createdAt: timestamp
  updatedAt: timestamp

trips/{tripId}/schedules/{scheduleId}
  date: string             // "2026-12-01"
  startTime: string        // "09:30"、未定なら ""
  endTime: string
  title: string
  category: "move" | "food" | "sightseeing" | "hotel" | "other"
  reservation: "none" | "todo" | "done"
  place: string
  url: string              // 予約ページや地図などのリンク
  memo: string
  createdAt: timestamp

users/{uid}/packingItems/{itemId}
  name: string
  checked: boolean
  createdAt: timestamp
```

### セキュリティルールの方針
- `trips/{tripId}`: ログイン中のユーザーのメールアドレスが `memberEmails` に含まれていれば読み書きできる
- 作成時は、`ownerUid`・`ownerEmail` が自分で、`memberEmails` が自分だけであることを確認する
- 削除と `memberEmails` の変更は作成者（`ownerUid`）だけができる。作成者はメンバーから外せない
- `schedules` は、親の `trips` のメンバーであれば読み書きできる
- `users/{uid}/packingItems` は本人だけが読み書きできる
